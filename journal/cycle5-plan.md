## E13: TU-free build (assumption: a compiler needs the whole TU to emit good code). Revised after review.
- Question: if Lua 5.4.6's core files are built so that each extern function is compiled in its own object without the bodies of other extern functions, does Lua pass its test suite, and how much does the program slow down?
- Build rule: for each extern target in a core file, compile that file's preprocessed text with every *other* extern function body replaced by its prototype (`clang -O2`, the Makefile's exact flags). Statics stay; unused ones are dead-code-eliminated, so each worker effectively compiles only the target plus the statics it reaches. Keep only the target as a global symbol; statics become per-object local copies. Report E8-style slice sizes as a statistic.
- Measured effect: per-TU -O2 can inline and infer attributes for extern callees in the same file (e.g. luaV_tointegerns, luaV_mod and luaV_idiv into luaV_execute); here it cannot. That loss is what the ratio measures.
- Scope: core files lvm, ldo, ltable, lgc, lapi, lstring, lfunc, ltm, lobject, ldebug, lstate, lauxlib, lcode, lparser, llex, lzio, lmem, lundump, ldump. Library files are left as they are, since each exports one `luaopen_*` that reaches every static, so it's a single slice anyway. Report targets per file.
- Safety check, fails the build if violated: no split file may have an address-taken static function or a non-const file-scope or function-local static. Copies of those would be observably distinct. A reviewer's grep claimed there were none. The check found 17 address-taken statics in 6 files; only `boxgc` (4 lauxlib targets) and `dothecall` (5 lgc targets) are reached by more than one target. **Amended rule:** an address-taken static reached by one target stays static. One reached by several targets becomes a single hidden-visibility global with a TU-unique name, defined in exactly one object; the other objects get its prototype.
- Correctness: the official `lua-5.4.6-tests` in basic mode.
- Performance: 5 fixed benchmark programs (fib, binary-trees, spectral-norm, n-body, a string-ops loop), with outputs checked against the baseline. The main metric is instructions retired, with cycles alongside (`perf stat -r 10`, `taskset`, baseline and candidate runs interleaved). Noise floor: the baseline rebuilt with 3 shuffled link orders.
- Number: geomean instructions ratio (TU-free / per-TU -O2), with a confidence interval, and the same for cycles.
- Rule: tests pass and the ratio's interval lies wholly ≤1.03 means TU-free compilation is viable at no measurable cost for this program. Interval wholly >1.10, or any test failure, means cross-function knowledge within the TU is load-bearing; report which functions, and treat a test failure first as a likely transformation bug. Interval wholly within 1.03–1.10 means viable at a measured cost. An interval straddling a boundary is **inconclusive**.
- Caveat for the write-up: passing basic-mode tests supports this Lua configuration, not general correctness.
